# 引用、复用和后续补测

## 引用一项结果

建议同时记录本仓库版本、结果系列、GPU、参数集、操作、批量、输入分布、计时范围、来源ID及对应来源文件SHA256。保存原来源文件名和包内路径，便于他人追溯同一记录。

分享汇总数值时，保留统计方法、比值方向、重复层级和适用范围。不要将固定输入的计时次数写成独立语料数，也不要把工具过程与其检查子项重复计数。

本整理未虚构作者、论文、DOI或统一许可证。输入材料中已有的署名和许可不因目录调整而改变；本发布包未另行授予统一的数据或代码许可。项目方确定发布许可后，应在仓库根目录补充相应文件。

## 加入新一轮数据

- 保留新输入包和原始文件，不覆盖旧轮次；记录包名、设备、时间或原始运行标识。
- 将原始CSV/TSV按字节入库，更新来源路径到SHA256的映射；从日志提取的表放入派生目录。
- 区分新增测量、旧结果再导出、同二进制漂移对照、资格检查和真正的性能替换。若替换结果，写清被替换项及依据。
- 记录输入分布、二进制身份、计时范围、重复层级、状态和未覆盖部分。来源没有的字段留空或注明未提供，不推造运行标识或置信区间。
- 更新归一化记录并重建结果，检查来源关联、正确性层级和目录链接；保留版本变化说明与实际核验记录。

## 报告整理问题

问题描述应给出仓库版本、文件相对路径、来源ID、行号或JSON定位，并说明预期与实际差异。若涉及原始文件内容，附上SHA256可避免把不同副本或轮次混淆。

涉及分类、字段数和来源引用的修正应留痕；涉及原始实验结论的变更，应提供新的来源证据。原始文件仍保留原样，新的解释放入派生结果和说明。

# 整理方法与解释边界

## 输入与保真

整理范围是六个交付 ZIP，包括其清点过程中识别出的嵌套归档。全部原始 CSV/TSV 按字节提取并用 SHA256 去重；保留每个来源路径到唯一内容文件的映射。原始表不修改编码、换行、列名、数值或状态。

JSON、日志和其他非表格证据中的选定记录被提取为派生表或归一化记录。它们放入 `data/derived/` 并与原始表分开，不能被描述为原 ZIP 中已有的 CSV。小型原始证据另存于 `data/evidence/`；未选存的大型二进制、完整日志或截图不属于这个发布包。来源索引分别标记随包文件、派生表和仅保留出处的材料，来源路径存在不代表该文件已随包提供。

## 从证据到展示

1. 原始表与选存证据保留原文，来源索引给出包名、路径、SHA256和定位信息。
2. 六包归一化记录统一常用设备、参数、操作、数值与来源字段；它们是整理后的输入层。
3. 重建程序按已公开规则分类、生成结果视图、实验导航和统计摘要。
4. Excel 为结果视图提供筛选和阅读格式；下载校验另行检查文件完整性。

重建可验证“随包归一化记录如何生成发布结果”。它不自动从六个原 ZIP 重新完成所有人工识别与提取，也不证明每项源实验结论独立成立。需要审计提取含义时，应结合原始表、证据和来源定位。

## 去重、修订与计数

重复文件按原字节去重，不把重复出现的同源数据当作新的样本。路径数、表数、数据行数、进程数、计时次数和独立实验数分别解释。

主性能保留三个系列：4090 历史 R02 的27条、4090 10/18＋10/19修订的27条、5090 E03的9条。4090修订系列有3条来源明确的复测替换；旧测仍可追溯，但不与复测合并扩大样本。5090四分布补测进入消融，4090修补资格进入正确性和诊断，不替换63条主性能。

正确性视图的1,722行包含不同记录层级。工具过程与其子项、故障注入与恢复阶段、身份审计与摘要可能描述同一轮运行的不同方面，不能把行数直接作为独立试验次数。

v4修正表索引的字段数元数据：不再把提取时追加的两列当作原始列；无表头文件按实际记录宽度计数，并显式记录表头属性和宽度变化。4090修补包的无表头cases.tsv也按数据行解释，首行未被丢弃。实验来源引用的修正单独记录。上述调整不改变原始文件、原始数值或原始数据行数。

## 性能与统计

只有 GPU、代码和二进制版本、输入分布、对照实现、批量、计时范围与归约方法匹配时，结果才可直接比较。不同设备与系列不合成总加速比。配对比值的几何均值不等于合并耗时之比。

历史 R02 使用来源所述的进程中位数与区组bootstrap口径；其他系列保留其均值、进程配对和重复规则。未报告置信区间时不补造。观测min/max只描述已见范围。固定输入的多次进程内计时不代表多份独立语料。

设备驻留计时未必包含主机准备和传输，不能直接作为应用端到端延迟。旧Dilithium v3.1对照、同二进制漂移对照、路径未激活对照和真实优化消融分别保留限定条件。

## 正确性和版本资格

PASS不扩展到未测试工具、未覆盖输入或其他二进制。4090修补后的独立测试程序资格不追认历史性能模块；来源中的模块哈希不一致被保留。故障恢复的部分覆盖与非零残留字段仍按原记录解释。

5090的告警、停止和未运行项未由较好的性能数值覆盖。只保存最终计时输出的检查，不被解释为每次中间输出都已独立核验。来源引用但未随包提供的外部归档只记为来源报告，不能算作本包独立复核。

此次工作只整理、复算和校验现有材料，未重新执行 GPU 实验、KAT 或 sanitizer，也未修改项目算法或测试程序。
